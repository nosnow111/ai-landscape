🗃️ AI in Major Databases

Modern databases and data platforms have rapidly integrated AI and ML capabilities directly into their core engines, eliminating the need to move data to external systems for inference and model training. By 2026, vector search has become a foundational capability across virtually all major data platforms, with 75% of enterprise AI applications depending on vector search capabilities according to ACI Infotech. The competitive landscape is shifting from purpose-built vector databases toward general-purpose platforms with embedded AI, as Snowflake, Google, Amazon, Databricks, MongoDB, and PostgreSQL extensions all offer native LLM integration, embedding generation, and semantic search within their existing infrastructure.

Snowflake

Vector Search

Cortex AI

🔗 https://www.snowflake.com/en/data-cloud/cortex/

Snowflake Cortex AI provides a suite of fully managed ML and LLM functions directly within the Snowflake AI Data Cloud. It includes Cortex LLM Functions (COMPLETE, SUMMARIZE, SENTIMENT, TRANSLATE, EXTRACT_ANSWER) that run inference on leading models including Mistral, LLaMA, and Snowflake Arctic without data leaving the platform. Cortex Search enables hybrid vector and keyword search over enterprise data, while Cortex Analyst allows natural language querying of structured data. Snowflake Postgres (generally available in 2026) now runs natively in the AI Data Cloud with pgvector support, and the Unistore capability eliminates the transactional-analytical divide for real-time AI applications. Cortex Fine-tuning allows organizations to fine-tune open-source LLMs on their proprietary Snowflake data.

LLM Integration: Native integration with Mistral, LLaMA 3, Snowflake Arctic, Reka, and Jamba models via Cortex LLM Functions. Supports bring-your-own-model via external functions and integrates with Hugging Face. Cortex Analyst connects LLMs directly to structured Snowflake tables for natural language querying.

Cortex AI functions are billed in Snowflake credits. LLM inference costs vary by model and token count, typically ranging from 0.013 to 0.20 credits per 1,000 tokens depending on model size. Cortex Search is priced on indexed data volume and query volume. Snowflake Postgres pricing follows standard Snowflake compute and storage credit consumption. Overall costs are bundled into existing Snowflake contracts for many enterprise customers.

Google BigQuery

Vector Search

BigQuery ML + Vertex AI Integration

🔗 https://cloud.google.com/bigquery/docs/bqml-introduction

BigQuery ML enables data analysts and data scientists to create and execute machine learning models directly within BigQuery using standard SQL statements, removing the need to export data. Supported model types include linear regression, binary and multiclass logistic regression, k-means clustering, matrix factorization, time series forecasting (ARIMA+), XGBoost, deep neural networks, AutoML Tables, and imported TensorFlow or PyTorch models. BigQuery's deep integration with Vertex AI allows calling hosted LLMs including Gemini models directly from SQL using ML.GENERATE_TEXT and ML.EMBED_TEXT functions. BigQuery Vector Search provides approximate nearest neighbor search over embedding columns stored natively in BigQuery tables, enabling semantic search and RAG pipelines without a separate vector store.

LLM Integration: Deep native integration with Google Gemini (1.0 Pro, 1.5 Pro, 1.5 Flash) and PaLM 2 models via ML.GENERATE_TEXT SQL function. Supports text embedding generation via ML.EMBED_TEXT using Gecko embedding models. Remote model connections allow calling any Vertex AI endpoint from BigQuery SQL, enabling access to the full Vertex AI Model Garden including Claude, Llama, and Mistral models.

BigQuery ML model training is charged per TB of data processed similar to standard BigQuery query pricing. LLM inference via ML.GENERATE_TEXT is billed through Vertex AI at standard Vertex AI pricing per 1,000 characters or tokens depending on the model. Vector Search queries are charged per query and index storage. PostgreSQL

Vector Search

pgvector + pgai

🔗 https://github.com/pgvector/pgvector

pgvector is an open-source PostgreSQL extension that adds vector similarity search capabilities directly to any PostgreSQL instance, making it the lowest-friction path to vector search as no new infrastructure is required. It supports storing vector embeddings as a native column type, exact and approximate nearest neighbor search using IVFFLAT and HNSW indexing algorithms, and L2 distance, inner product, and cosine similarity operators. pgai (from Timescale) extends pgvector by adding SQL functions to call embedding models and LLMs directly from PostgreSQL, enabling chunking, embedding generation, and LLM inference through SQL queries. pgvector integrates natively with Snowflake Postgres (announced February 2026) and works within existing PostgreSQL security, backup, and replication frameworks. The combination allows building full RAG pipelines entirely within the database.

LLM Integration: pgai provides native SQL integration with OpenAI, Anthropic Claude, Cohere, and Ollama (for local models) directly from PostgreSQL functions. Embeddings can be auto-generated and kept in sync with source data via pgai vectorizer. Snowflake Postgres with pgvector connects to Cortex AI models. Standard PostgreSQL deployments on AWS RDS, Azure Database, Google Cloud SQL, Supabase, and Neon all support pgvector.

pgvector and pgai are open-source and free to use. Costs depend on the PostgreSQL hosting environment: self-hosted has only infrastructure costs, while managed services like Supabase (free tier available, pro from $25/month), Neon (free tier available, from $19/month), AWS RDS (standard RDS instance pricing), and Timescale Cloud (from $17.63/month) add their own pricing layers. LLM API calls made via pgai are billed by the respective LLM provider at their standard rates.

MongoDB Atlas

Vector Search

Atlas Vector Search

🔗 https://www.mongodb.com/products/platform/atlas-vector-search

MongoDB Atlas Vector Search enables storing, indexing, and querying vector embeddings natively within MongoDB Atlas collections alongside operational document data, eliminating the need for a separate vector database. It uses a hierarchical navigable small world (HNSW) algorithm for approximate nearest neighbor search and supports filtering by document metadata fields simultaneously with vector similarity queries (pre-filtering and post-filtering). Atlas Vector Search integrates natively with popular AI frameworks including LangChain, LlamaIndex, Haystack, and Spring AI. The $vectorSearch aggregation pipeline stage allows combining semantic search with MongoDB's full aggregation pipeline capabilities. Atlas also supports hybrid search combining vector similarity with full-text Atlas Search (BM25) for improved retrieval precision in RAG applications. Quantization support reduces index size and improves query performance for large-scale deployments.

LLM Integration: Atlas Vector Search integrates with OpenAI (including text-embedding-3-small and text-embedding-3-large), Cohere Embed, Google Vertex AI Embeddings, Amazon Bedrock Titan Embeddings, Hugging Face, Nomic, and Voyage AI for embedding generation. LLM orchestration is supported via LangChain, LlamaIndex, and direct API integrations. Atlas Vector Search is available on M10 and above dedicated clusters. Pricing is based on the underlying Atlas cluster tier (M10 starts at approximately $0.08/hour, M30 at approximately $0.54/hour). Vector index storage is charged at Atlas storage rates ($0.25 per GB/month on most cloud providers). There is no separate per-query charge for vector search beyond the cluster compute cost. Atlas Flex (serverless successor) pricing is consumption-based per read/write processing unit. Free tier (M0) does not support Atlas Vector Search.

📊 AI Observability & Cost Monitoring

AI observability matters because LLM applications introduce unique failure modes—hallucinations, latency spikes, runaway token costs—that traditional APM tools were not designed to catch. As the LLM observability platform market grows from $2.69 billion in 2026 toward $9.26 billion by 2030 at a 36.2% CAGR, teams that invest in proper monitoring gain the ability to trace prompts end-to-end, attribute costs to users or departments, and evaluate output quality before problems reach production. Gartner predicts LLM observability investments will account for 50% of all GenAI deployments by 2028, up from just 15% in early 2026, signaling that this tooling is rapidly becoming non-negotiable.

💡 Cost Reduction Tips

  • •Implement prompt caching and request deduplication: tools like Helicone offer built-in caching so identical or near-identical prompts return stored responses without hitting the LLM API, which can reduce redundant spend by 20–40% for applications with repetitive query patterns
  • •Use observability data to right-size your model selection: trace-level cost breakdowns in tools like Langfuse or Helicone reveal which tasks consume the most tokens, enabling you to route simpler subtasks to smaller, cheaper models while reserving frontier models only for high-complexity requests
  • •Set user- and team-level spend budgets and rate limits: platforms like Helicone and LangSmith support cost attribution by user session or department, allowing you to enforce hard caps before a single runaway agent loop or misconfigured batch job generates unexpected five-figure API bills
  • •Audit and trim prompt bloat through prompt versioning: prompt management features in LangSmith and Langfuse let you A/B test shorter prompt variants against quality metrics, as unnecessary system prompt verbosity and redundant few-shot examples often account for 15–30% of token spend with no measurable quality benefit
