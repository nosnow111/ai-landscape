AI in Major Databases

Modern databases have evolved far beyond simple data storage, now embedding sophisticated AI and ML capabilities directly into the data platform to eliminate the need to move data to external systems. From native LLM integrations and vector search to in-database model training and inference, these platforms allow developers and data scientists to run AI workloads where the data already lives. This convergence of databases and AI dramatically reduces latency, simplifies architecture, and lowers the barrier to building intelligent applications.

Snowflake (Cortex AI)

Vector Search

Snowflake Cortex AI

🔗 https://docs.snowflake.com/en/guides-overview-ai-features

Snowflake Cortex AI provides a suite of fully managed ML and LLM functions directly within Snowflake SQL. It includes COMPLETE() for LLM text generation, SENTIMENT() and SUMMARIZE() for NLP tasks, CLASSIFY_TEXT() for zero-shot classification, and Cortex Search for hybrid vector + keyword search. Cortex Analyst enables natural language querying of structured data. Models from Mistral, Meta Llama, Reka, and others are available without any infrastructure management. Fine-tuning is supported via Cortex Fine-tuning, and ML functions like FORECAST() and ANOMALY_DETECTION() handle time-series use cases natively.

LLM Integration: Native support for Mistral Large/7B, Meta Llama 3.1/3.3 (8B, 70B, 405B), Reka Flash, Snowflake Arctic, and others via Cortex LLM functions. Models are called directly in SQL using functions like SNOWFLAKE.CORTEX.COMPLETE(). Cortex Search provides hybrid retrieval combining dense vector and BM25 keyword search for RAG pipelines.

Priced in Snowflake credits. LLM functions are billed per token processed (e.g., Llama 3.1 8B costs ~0.0000225 credits per token). Cortex Search is billed for documents indexed and queries served. ML functions like FORECAST() are billed per compute credit. Costs vary significantly by model size and region. Free tier available for trial accounts.

Google BigQuery (BigQuery ML + Vertex AI)

Vector Search

BigQuery ML + Vertex AI Integration

🔗 https://cloud.google.com/bigquery/docs/bqml-introduction

BigQuery ML allows users to create, train, and run ML models directly using standard SQL syntax, supporting logistic regression, k-means clustering, matrix factorization, boosted trees (XGBoost), deep neural networks (DNNs/AutoML), and time-series ARIMA+ forecasting. Through native Vertex AI integration, BigQuery can call hosted Gemini models for text generation, embeddings, and multimodal tasks via ML.GENERATE_TEXT() and ML.EMBED_TEXT(). Vector search is supported via the VECTOR_SEARCH() function and native vector indexes on BigQuery tables, enabling scalable approximate nearest-neighbor search for RAG architectures.

LLM Integration: Deep integration with Google Vertex AI and Gemini models (Gemini 1.5 Flash, Gemini 1.5 Pro, Gemini 2.0). Remote models are registered as BigQuery ML models via CREATE MODEL with REMOTE_WITH_CONNECTION. ML.GENERATE_TEXT() enables text generation and ML.EMBED_TEXT() produces vector embeddings in SQL. Supports PaLM 2 legacy models and open models hosted on Vertex AI Model Garden including Llama and Mistral variants.

BigQuery ML model training is free for linear/logistic regression; AutoML and DNN training incur Vertex AI training costs. Inference via GENERATE_TEXT() is billed at Vertex AI pricing per 1K characters or tokens depending on model (e.g., Gemini 1.5 Flash is ~$0.075/1M input tokens). Vector index creation and VECTOR_SEARCH queries are billed as standard BigQuery compute (on-demand: $6.25/TB scanned or flat-rate slots). BigQuery ML predictions are billed per query.

PostgreSQL (pgvector + pgai)

Vector Search

pgvector + pgai Extensions

🔗 https://github.com/pgvector/pgvector

pgvector is an open-source PostgreSQL extension that adds a native vector data type and enables exact and approximate nearest-neighbor search using IVFFLAT and HNSW indexing algorithms, making PostgreSQL a capable vector database for semantic search and RAG applications. pgai (developed by Timescale) extends this by enabling direct calls to external LLM APIs (OpenAI, Ollama, Cohere, Anthropic) from within SQL functions, allowing embedding generation, text completion, and model inference without leaving the database. Together they allow developers to store embeddings alongside relational data and query them with standard SQL joins and filters.

LLM Integration: pgai provides SQL wrapper functions to call OpenAI (text-embedding-3-small, GPT-4o), Ollama (local models), Anthropic Claude, Cohere, and others directly from PostgreSQL functions. For example, ai.openai_embed() generates embeddings inline during INSERT or SELECT. Vectorizer (part of pgai) automates embedding creation and synchronization for table columns. No native LLM hosting — it proxies to external APIs using stored API keys in database secrets.

Both pgvector and pgai are open-source (PostgreSQL License and Apache 2.0 respectively) and free to install on any self-hosted PostgreSQL instance. When using managed services like Timescale Cloud, Supabase, or AWS RDS/Aurora PostgreSQL with pgvector, you pay standard compute/storage fees for the database instance. LLM API calls made through pgai are billed directly by the respective provider (e.g., OpenAI API pricing). No additional licensing fees for the extensions themselves.

Amazon (Aurora ML + Redshift ML)

Vector Search

Aurora ML + Redshift ML + Amazon Bedrock Integration

🔗 https://docs.aws.amazon.com/AmazonRDS/latest/AuroraUserGuide/aurora-ml.html

Aurora ML enables Amazon Aurora (MySQL and PostgreSQL-compatible) to invoke ML models hosted on Amazon SageMaker and Amazon Comprehend directly via SQL functions, allowing sentiment analysis, fraud detection, and custom inference without ETL. Redshift ML allows Amazon Redshift users to create, train, and deploy ML models using SQL with CREATE MODEL syntax, automatically leveraging SageMaker Autopilot under the hood. Both services also integrate with Amazon Bedrock for generative AI capabilities including text generation, summarization, and embedding generation from foundation models, and pgvector support is available on Aurora PostgreSQL for vector workloads.

LLM Integration: Amazon Bedrock integration allows Aurora and Redshift to call foundation models including Amazon Titan (text and embeddings), Anthropic Claude 2/3, Meta Llama 3, Mistral, Cohere Command, and AI21 Jurassic via SQL. AI Observability & Cost Monitoring

AI observability is critical for understanding how large language models behave in production, helping teams debug issues, optimize performance, and control costs. As LLM applications scale, without proper monitoring it becomes nearly impossible to trace failures, measure quality, or identify expensive inefficiencies in prompts and model usage. These tools provide the visibility needed to build reliable, cost-effective AI systems.

💡 Cost Reduction Tips

  • •Implement prompt caching and semantic caching: use tools like Helicone's built-in cache or Redis with embedding similarity checks to serve repeated or near-identical queries from cache, which can reduce API call volume by 20-60% for applications with repetitive inputs.
  • •Right-size your model selection by routing queries based on complexity: use smaller, cheaper models such as GPT-4o-mini or Claude Haiku for simple classification or extraction tasks, and reserve expensive frontier models only for reasoning-heavy tasks that genuinely require their capability.
  • •Audit and compress your prompts regularly: system prompts often grow bloated over time with redundant instructions; trimming unnecessary tokens, using concise language, and removing duplicate context can reduce costs by 10-30% without degrading output quality.
  • •Set hard spend limits and monitor per-feature or per-user costs: use observability tools to tag requests with metadata, then analyze which features, user segments, or prompt templates drive the most spend, allowing you to prioritize optimizations where they have the greatest financial impact.
