PostgreSQL

Vector Search

pgvector + pgai

pgvector is an open-source PostgreSQL extension that adds vector similarity search capabilities, enabling storage and querying of high-dimensional vectors alongside relational data. It supports exact and approximate nearest neighbor search using IVFFLAT and HNSW indexing algorithms. pgai (from Timescale) extends PostgreSQL further by adding functions to call LLM APIs (OpenAI, Ollama, Cohere) directly from SQL, generate embeddings, and perform vectorizer automation. Together they enable full AI-native workflows within a standard PostgreSQL database without external services.

LLM: pgai provides SQL functions to call OpenAI (chat completions, embeddings), Ollama (local LLMs), Cohere, and Anthropic APIs directly from PostgreSQL. Functions include ai.openai_chat_complete(), ai.openai_embed(), ai.ollama_chat_complete(). pgai Vectorizer automates embedding generation and synchronization. Available on managed services like Timescale Cloud and Supabase.

pgvector and pgai are open-source and free to use on self-hosted PostgreSQL. Managed hosting costs depend on provider (e.g., Timescale Cloud, Supabase, AWS RDS, Azure). LLM API calls via pgai are billed by the respective third-party provider (OpenAI, Cohere, etc.) at their standard rates. No additional licensing fee for the extensions themselves.

https://github.com/pgvector/pgvector

AI Observability & Cost Monitoring

Cost Reduction Tips

  • •Implement semantic caching by storing embeddings of past prompts and returning cached responses for semantically similar queries, which can reduce redundant API calls by 20-40% for applications with repetitive user inputs
  • •Right-size your model selection by routing simpler or lower-stakes tasks to smaller, cheaper models like GPT-4o-mini or Claude Haiku while reserving larger models like GPT-4o or Claude Opus only for complex reasoning tasks that genuinely require them
  • •Optimize prompt design by reducing unnecessary verbosity in system prompts, trimming conversation history with summarization techniques, and using structured output formats to minimize response token counts without sacrificing quality
  • •Set hard budget limits and usage alerts at the provider and observability layer levels, and regularly audit cost attribution by feature or user segment so you can identify and deprecate low-value high-cost workflows before they accumulate significant spend
